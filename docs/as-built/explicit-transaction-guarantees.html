Explicit transaction guarantees

Repo xshaheen/headless-framework Commit 3ba5984cf (base e26538d80) Generated 2026-09-14T20:40:37Z status: complete

    Executive summary

    Two stacked pull requests (#895 and #897) make the transaction guarantees of Headless Messaging and Headless Jobs explicit and rebuild the commit-coordination contract they rest on. Publishing now has three delivery modes with Durable as the default, job scheduling has a per-call RequireAtomicEnlistment requirement that recurring definitions also honor, and both consumers reach the caller's live transaction through a minimal register-only ICommitCoordinator. The in-memory and durable-work coordination packages are deleted, SQL Server keeps only explicit signalling, and every provider shares one Core runner. The code is complete on branch head 3ba5984cf; both PRs await review and merge.

    What a new developer must know first

    • A Durable publish outside any transaction is stored first and dispatched by the relay; there is no silent direct send. Coordinated requires a compatible live transaction and fails at startup when no coordinator is registered. Direct bypasses storage. docs/llms/messaging.md:107-111
    • The ambient coordinator is an AsyncLocal. Every consumer captures ICurrentCommitCoordinator.Current synchronously before its first await, and every scope pushes and pops its ambient frame synchronously in the owning frame; an async dispose strands the frame. src/Headless.CommitCoordination.Abstractions/ICommitScopeFactory.cs:20-26
    • OnCommit callbacks run once, in registration order, without a cancellation token, and are never recovered after a crash. Nothing runs on rollback; rollback discards by disposing the scope. src/Headless.CommitCoordination.Abstractions/ICommitCoordinator.cs:13-26
    • Who signals depends on the provider: the EF interceptor signals on the commit or rollback edge; raw SQL Server and PostgreSQL callers signal explicitly or use ExecuteCoordinatedTransactionAsync, which signals for them. docs/llms/commit-coordination.md:68-74
    • CI runs unit tests only. The provider and consumer integration suites run locally with Docker and are the only proof for database behavior. Makefile:227-238

    Architecture

    Dependencies point one way: Messaging and Jobs depend on Headless.CommitCoordination.Abstractions only; the providers depend on Core; nothing in coordination knows about Messaging or Jobs. At runtime a unit of work opens one ICommitScope through a provider, the scope pushes its ICommitCoordinator onto an AsyncLocal stack, consumers discover it through ICurrentCommitCoordinator.Current, write their row on the scope's Relational handle, and register an OnCommit callback. The scope owner signals the outcome; the coordinator drains callbacks in-process. Two hosted services complete the picture: the Jobs post-commit worker that executes signals off the commit thread, and the EF startup gate that proves the interceptor fires. docs/llms/commit-coordination.md:45-49 src/Headless.CommitCoordination.Core/Setup.cs:28-42

    Raw ADO transaction through the shared runner

    SQL Server and PostgreSQL expose no commit edge, so the helper signals for the caller. ExecuteCoordinatedTransactionAsync on either connection type resolves a logger, then delegates to CoordinatedTransactionRunner.ExecuteAsync: open the connection if closed, begin the transaction, enlist synchronously in the helper's frame, run the operation, commit, signal Committed. When the operation or the commit throws, the runner signals RolledBack, logs a fault from that signal at Warning, and rethrows the original exception. A post-commit drain fault is logged through the provider's delegate and the result is still returned, because a retry would double-apply committed work and the relay recovers it.     Design decisions and trade-offs

    Breaking changes instead of compatibility shims verified

    Context
    The project is greenfield; the old contract (Auto mode, CommitContext, join and child scopes, rollback callbacks, the capability bag, the SQL Server diagnostic probe) promised more than the runtime delivered.
    Chosen
    Remove the surfaces outright, renumber DeliveryMode, delete two packages, and document a migration table in the PR body.
    Alternatives
    Keep Auto as an alias; prune inside the general framework instead of rebuilding.
    Consequences
    Consumers recompile and change call sites; the shipped contract equals the documented one.
    Evidence
    docs/plans/2026-09-13-1536-refactor-explicit-transaction-guarantees-plan.md:37-46 CLAUDE.md:10-11

    Durable is the default; no mode sends directly by omission verified

    Context
    The former Auto mode silently downgraded to a direct send when no transaction was active, so the guarantee depended on call-site context.
    Chosen
    Durable stores first inside a compatible scope or standalone; Coordinated is requested-side strictness that resolves to durable capture; Direct is an explicit opt-out.
    Alternatives
    A transaction-bound facade such as tx.Bus instead of ambient discovery.
    Consequences
    A publish outside any transaction now costs one storage write and a relay hop; high-rate events opt out per type.
    Evidence
    docs/llms/messaging.md:113-118 src/Headless.Messaging.Core/Internal/DeliveryDecisionResolver.cs:178-185

    A minimal register-only coordinator, rebuilt in place verified

    Context
    Messaging and Jobs used only Relational, OnCommit, and scope-local state; join scopes, rollback callbacks, and the capability bag had no production caller.
    Chosen
    ICommitCoordinator keeps State, Relational, OnCommit(Func<ValueTask>), and two GetOrAdd overloads; ICommitScopeFactory has one method; the conformance harness is the specification.
    Alternatives
    Prune the general framework while keeping its extension points.
    Consequences
    Rollback discards by disposal; every scope is an independent root; the internal constructors stay constructible for the Messaging unit tests.
    Evidence
    docs/plans/2026-09-13-1536-refactor-explicit-transaction-guarantees-plan.md:159-163 src/Headless.CommitCoordination.Abstractions/ICommitCoordinator.cs:36-38

    Signals are idempotent per outcome verified

    Context
    The EF inbox runners signal explicitly and the interceptor signals on the same edge; the old design warned about the racing second signal.
    Chosen
    A repeated same-outcome signal is a silent no-op; a conflicting later signal is logged at Warning and ignored; the first terminal claim wins against a racing dispose.
    Alternatives
    A single-signal rule enforced by the runners avoiding the interceptor.
    Consequences
    Two owners may signal the same transaction safely; a genuine disagreement about the outcome is visible in the log.
    Evidence
    docs/plans/2026-09-13-1536-refactor-explicit-transaction-guarantees-plan.md:160-160 src/Headless.CommitCoordination.Core/CommitCoordinator.cs:111-130

    The EF interceptor owns the transaction-to-scope map verified

    Context
    Eviction used to depend on an interceptor event, and a commit that throws but is probe-confirmed raises none; Npgsql reuses one NpgsqlTransaction instance per connection.
    Chosen
    Enlistment registers the entry, the wrapper scope evicts it on dispose, every terminal edge evicts before signalling, and a finished leftover is replaced on re-enlistment.
    Alternatives
    A separate public signal-source service (deleted).
    Consequences
    The messaging EF storages no longer need InternalsVisibleTo into the provider; a scope that is never disposed and never reaches an edge stays in the map.
    Evidence
    src/Headless.CommitCoordination.EntityFramework/CommitCoordinationTransactionInterceptor.cs:16-35 src/Headless.CommitCoordination.EntityFramework/CommitCoordinationTransactionInterceptor.cs:72-74

    SQL Server takes the PostgreSQL shape: explicit signal, no out-of-band detection verified

    Context
    Neither driver exposes a commit edge. SQL Server carried a diagnostic listener, probe, hosted service, and options that only approximated what an explicit signal states exactly.
    Chosen
    One Core runner body shared by both packages; the helper signals for the caller; direct enlistment signals explicitly; an un-signalled dispose after completion warns.
    Alternatives
    Keep the SQL Server diagnostic detection as a fallback.
    Consequences
    The SQL Server package loses its options and hosted service; a caller that forgets to signal sees a warning and no drain.
    Evidence
    docs/solutions/architecture-patterns/coordination-domains-boundary.md:77-85 src/Headless.CommitCoordination.Core/CoordinatedTransactionRunner.cs:22-105

    Jobs post-commit side effects move to a hosted worker verified

    Context
    The commit callback must be synchronous and non-blocking on the committing thread, yet cron cache invalidation cannot be dropped.
    Chosen
    A bounded channel of signal records drained by one hosted service, with a drop counter; cron invalidation stays inline with a 30 s bound; PostCommitDrainTimeout removed.
    Alternatives
    Coalescing signals, deferred until the drop counter shows pressure.
    Consequences
    Signals can be dropped under a burst of more than 1,024 pending commits; the row is committed regardless and the poll sweep recovers it.
    Evidence
    docs/plans/2026-09-13-1536-refactor-explicit-transaction-guarantees-plan.md:157-158 src/Headless.Jobs.Core/Managers/JobsManager.CommitCoordination.cs:173-176

    Savepoint-blind callbacks and EF pre-commit replay stay as they are verified

    Context
    A callback registered inside a savepoint that is later rolled back still runs when the outer transaction commits; the plain DbContext helper replays the whole operation for a failure before commit starts.
    Chosen
    Document both as non-defects; the Headless save pipeline honors CommitRetryGuard and does not replay.
    Alternatives
    Savepoint-aware registration; a replay-safe helper.
    Consequences
    Jobs tolerates the phantom signal because the worker re-reads due rows; a plain-context caller must not mix coordinated writes with a replaying strategy.
    Evidence
    docs/llms/jobs.md:186-186 src/Headless.CommitCoordination.Abstractions/ICommitCoordinator.cs:29-33

    The startup gate defaults to Warn verified

    Context
    A mis-wired interceptor means callbacks never drain, but the outbox row plus relay sweep still deliver.
    Chosen
    Probe once at host start with an empty transaction; warn by default, throw under Strict, skip under Disabled.
    Alternatives
    Environment-aware defaults (proposed in the learning, not implemented).
    Consequences
    A silent interceptor is visible in logs but not fatal unless the host opts in.
    Evidence
    src/Headless.CommitCoordination.EntityFramework/CommitInterceptorProbeOptions.cs:10-15 docs/solutions/architecture-patterns/startup-validation-gate-two-tier-mode-and-env-defaults.md:114-133

    Why the runner logs a rollback-signal fault at Warning rather than Error inferred

    Context
    When rolling back after an operation fault, disposing scope-local state can itself throw.
    Chosen
    Log at Warning and rethrow the operation's own exception.
    Alternatives
    Log at Error; wrap both exceptions in an AggregateException.
    Consequences
    The caller sees the real cause; the secondary fault is discoverable only in logs. The level choice is not recorded anywhere.
    Evidence
    src/Headless.CommitCoordination.Core/CoordinatedTransactionRunner.cs:60-77

    Known limitations and risks

    Risk

    Post-commit callbacks are process-local and never recovered. Durability of every side effect in this design rests on the outbox row or job row plus the consumer's own polling sweep; a host that disables or misconfigures those sweeps loses delivery on any crash between commit and drain. src/Headless.CommitCoordination.Abstractions/ICommitCoordinator.cs:13-20

    • Coordinated PRs are unmerged. Both PRs are green and quiet but awaiting review; CI for PR #897 was run by manual dispatch because the workflow only triggers for PRs into main. .github/workflows/ci.yml:3-7
    • Inbox runners can mask a post-commit drain fault. The explicit SignalAsync(Committed) shares the commit's try; a fault after a durable commit is re-probed and re-signalled as a no-op with no log. Wrap and log it like the other post-commit paths. inferred src/Headless.Messaging.Storage.PostgreSql.EntityFramework/Setup.cs:186-202
    • The interceptor map can retain a leaked scope. A scope that is never disposed and never reaches a commit or rollback edge stays in the map; the leaked ambient frame is the larger problem in that case. src/Headless.CommitCoordination.EntityFramework/CommitCoordinationTransactionInterceptor.cs:191-196
    • The PostgreSQL completion probe depends on driver behavior. It treats any InvalidOperationException from NpgsqlTransaction.IsolationLevel as "completed"; a driver change degrades to no warning, never to a false drain. src/Headless.CommitCoordination.PostgreSql/EnlistCommitCoordinationExtensions.cs:76-96
    • No shutdown gate for background drains. A synchronous EF commit edge or synchronous Dispose hands the drain to the thread pool and nothing waits for it at host stop. src/Headless.CommitCoordination.EntityFramework/CommitCoordinationTransactionInterceptor.cs:164-189
    • Jobs signals can be dropped under load. The channel holds 1,024 signals; a full channel drops with a counter and relies on the poll sweep. No coalescing exists. absent src/Headless.Jobs.Core/BackgroundServices/JobsPostCommitSignalService.cs:81-95
    • Raw ADO helpers have no transient-fault handling. No execution strategy and no driver exception classification. absent src/Headless.CommitCoordination.SqlServer/CoordinatedTransactionExtensions.cs:21-22
    • No metrics or spans in the coordination packages, and no outbox-age metric in Messaging; operators rely on the warnings listed under Observability. absent
    • Integration coverage runs only locally. The database-backed suites are excluded from CI; a semantics change can pass CI while breaking a provider. Makefile:305-307
    • Small leftovers. CommitProbeMode in Abstractions now has one consumer (the EF gate); _RejectDirectCronPersistence is self-described as unreachable; the harness duplicates about fifteen lines of logger-scope plumbing between two capturing loggers. src/Headless.Jobs.Core/Managers/JobsManager.cs:314-321
    • Provisioned but unused dependencies: none found in the changed packages. The deleted packages (Headless.CommitCoordination.InMemory, Headless.CommitCoordination.DurableWork) are removed from the expected-package list. eng/expected-packages.txt

    Extension guide

    To add a new raw-ADO commit-coordination provider

    1. Create src/Headless.CommitCoordination.<Provider>/ with the Headless SDK and a project reference to Headless.CommitCoordination.Core; add the project to headless-framework.slnx and the package name to eng/expected-packages.txt.
    2. Copy the PostgreSQL shape: a parameterless Add<Provider>CommitCoordination() in Setup.cs that delegates to AddCommitCoordination(). src/Headless.CommitCoordination.PostgreSql/Setup.cs:28-31
    3. Write EnlistCommitCoordination on the driver's connection type in the driver's namespace: build a RelationalCommitContext, call ICommitScopeFactory.Open synchronously, and return a scope that derives from ExplicitSignalCommitScope with a completion probe and the warning log. src/Headless.CommitCoordination.PostgreSql/EnlistCommitCoordinationExtensions.cs:55-96 src/Headless.CommitCoordination.PostgreSql/PostgreSqlCommitScope.cs:12-32
    4. Write the four ExecuteCoordinatedTransactionAsync overloads and delegate the body to CoordinatedTransactionRunner.ExecuteAsync with begin and enlist lambdas and a post-commit-fault logger. src/Headless.CommitCoordination.PostgreSql/CoordinatedTransactionExtensions.cs:143-165
    5. Add a unit project for the scope warning and setup, and an integration project whose fixture implements ICoordinatedTransactionFixture and derives the conformance pair. tests/Headless.CommitCoordination.Tests.Harness/ICoordinatedTransactionFixture.cs:14-48
    6. Add the package section to docs/llms/commit-coordination.md, its README, the provider table, and the root READMEs and index, following docs/authoring/AUTHORING.md.
    Pitfall

    Never push or pop the ambient frame from inside an async method. Open must run in the caller's frame and the scope's DisposeAsync must not be async; the pre-existing interceptor test catches a stranded frame as "disposed out of order". src/Headless.CommitCoordination.Core/CommitScope.cs:35-48

    To make a new consumer write inside the caller's transaction

    1. Register a null ICurrentCommitCoordinator with TryAddSingleton so the real one wins when AddCommitCoordination() ran. src/Headless.Jobs.Core/DependencyInjection/SetupJobs.cs:195-197
    2. Read Current as the first statement of the public method, before any await, and resolve the writer at capture so a mis-wire fails there. src/Headless.Jobs.Core/Managers/JobsManager.CommitCoordination.cs:21-35
    3. Treat a scope without Relational as not infectious; throw on a coordinator that is not Active or whose transaction is null; compare data source and database before binding. src/Headless.Jobs.Core/Managers/JobsManager.CommitCoordination.cs:44-67
    4. Call GetOrAdd<CommitRetryGuard> and PreventRetry() before the write when your write cannot be replayed from a change tracker. src/Headless.Messaging.Core/Internal/MessagePublisher.cs:137-147
    5. Register OnCommit with a callback that only hands work to a queue or channel and returns a completed ValueTask; do side effects elsewhere. src/Headless.Jobs.Core/Managers/JobsManager.CommitCoordination.cs:157-171
    6. Own recovery: a row committed in the transaction plus a sweep that finds it when the callback never runs.

    To change the delivery mode of one message type

    1. Call setup.Bus.ForMessage<T>(x => x.WithDeliveryMode(DeliveryMode.Direct)) or the Queue equivalent; the policy is keyed by declared type and lane. src/Headless.Messaging.Core/Registration/MessageBuilder.cs:25-31
    2. Do not combine a Direct policy with Delay or ScheduledAt calls; the resolver throws. src/Headless.Messaging.Core/Internal/DeliveryDecisionResolver.cs:168-176
    3. If the policy is Coordinated, ensure a commit coordinator is registered and the inbox tier is Transactional, or bootstrap fails. src/Headless.Messaging.Core/Configuration/MessagingCapabilityModel.cs:201-229
    Pitfall

    Direct ignores an active transaction entirely: the message goes to the transport before the caller commits, and a later rollback does not retract it. docs/llms/messaging.md:116-116
