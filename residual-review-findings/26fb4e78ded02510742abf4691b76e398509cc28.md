## Avoid redundant completed-retry lease updates

- Severity: P2
- Owner: downstream resolver
- Tracker: https://github.com/xshaheen/headless-framework/issues/803
- Source: `src/Headless.Messaging.Core/Processor/Dispatcher.cs` near the retry completion path

Successful and normally rescheduled retries durably clear their lease before
`RetryDispatchAttempt.CompleteAsync()` issues an exact-release command using the original lease identity.
The fenced predicate therefore makes the follow-up relational update a conservative no-op, but it still
costs an extra connection and command per completed retry.

The finding is intentionally deferred from PR #802 because eliminating that update safely requires widening
the sender and subscriber-executor outcome contracts. Issue #803 owns that follow-up while this PR remains
focused on shutdown correctness, generation fencing, and safe rolling-restart recovery.
