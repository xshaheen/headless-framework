public sealed class PlaceOrderHandler(IUnitOfWorkFactory factory, AppDbContext db)
{
    public async Task HandleAsync(Order order, CancellationToken ct)
    {

The hard parts are already written.

The details that decide whether a backend loses messages or runs a job twice.

Jobs never run twice

Workers claim rows with FOR UPDATE SKIP LOCKED on PostgreSQL and READPAST on SQL Server.

Messages commit with your data

The outbox row is written in your EF Core transaction and dispatched after commit.

Stale lock holders can't write

Every lease carries a monotonic fencing token that the next write checks.

Retries replay, not repeat

Fingerprinted admission returns the stored result instead of running twice.

Liveness from the database clock

Node membership never trusts a node's own clock to decide who is alive.

Tenants stay apart

Queries filter by tenant, cross-tenant writes throw, and messages carry the tenant.
